1. WHAT IS CLOUGUARD AI? (SIMPLE EXPLANATION & SUMMARY)
================================================================================
CloudGuard AI is an automated "mission control" and intelligent cloud advisor 
for Amazon Web Services (AWS). 

In simple terms:
- Companies spend thousands of dollars on AWS, and developers often forget about 
  unused servers, unattached hard drives, or leave security loopholes open 
  (like public databases or open ports to hackers).
- CloudGuard AI automatically scans the AWS account, identifies wasted money 
  and dangerous security misconfigurations, and uses Generative AI 
  (Amazon Bedrock Claude 3.5 Sonnet) to explain the issues in plain, simple 
  English (under 60 words) and show exact fix scripts.
- It displays everything in an interactive, clean, glassmorphic dashboard 
  with real-time posture scores, savings charts, and an AI chat assistant.

Key Highlights:
- Cost Optimization (FinOps): Finds idle EC2 servers, unattached EBS storage, 
  stale backups, unassigned IP addresses, and sudden billing spikes.
- Security Posture (CSPM): Detects open admin ports (SSH/RDP 22/3389), public 
  S3 buckets, IAM user accounts without Multi-Factor Authentication (MFA), 
  unrotated access keys, unencrypted volumes, and exposed databases.
- Generative AI Synthesis: Bedrock Claude 3.5 Sonnet generates executive 
  summaries and powers an interactive, grounded cloud assistant.
- 100% Safe & Read-Only: It cannot delete or terminate anything in your AWS 
  account; it only observes and advises.

2. HOW IT WORKS (HIGH-LEVEL FLOW)
================================================================================
1. AUDIT (Collectors):
   Scheduled AWS Lambda functions trigger hourly or daily via Amazon EventBridge.
   They connect to the target AWS account using a 100% read-only role and inspect
   EC2, EBS, S3, IAM, and RDS resources.

2. NORMALIZE & ENRICH (Normalizer Engine):
   Raw findings are converted into a standard format (Category, Severity, 
   Monthly Waste in $, Resource ID, and Evidence JSON).

3. INTELLIGENCE (Amazon Bedrock):
   Claude 3.5 Sonnet reads the finding and writes a concise plain-English 
   summary explaining what happened and how to fix it, while generating display-only 
   AWS CLI and Terraform remediation blueprints.

4. STORAGE & CACHING:
   Findings are stored in an encrypted Amazon DynamoDB table with Global 
   Secondary Indexes (GSIs) for sub-second queries. Raw audit snapshots are 
   archived to Amazon S3 with lifecycle transition to Glacier.

5. DELIVERY (Dashboard & API):
   An Amazon API Gateway routes requests to an API Lambda. The React frontend 
   fetches data and renders radial health gauges, 12-month cost charts, 
   the prioritized "Fix First" queue, and an AI chat slide-over.

3. COMPLETE LIST OF AWS RESOURCES & SERVICES USED
================================================================================

A. CORE SERVERLESS INFRASTRUCTURE & BACKEND
--------------------------------------------------------------------------------
1. Amazon Bedrock (Anthropic Claude 3.5 Sonnet)
   - Generates <= 60-word plain-English summaries for each finding.
   - Powers the RAG conversational AI Chat Advisor, answering natural questions 
     (e.g., "Why did my bill spike?" or "What are my top 3 critical risks?").
   - Uses Bedrock Guardrails to prevent hallucinations, enforce cloud-only topics, 
     and automatically mask sensitive information (PII).

2. AWS Lambda
   - Serverless execution engine running Python 3.12+ code with zero server management.
   - Runs the Cost Collectors, Security Collectors, Findings Normalizer, API Router, 
     and Weekly Email Digest generator.

3. Amazon DynamoDB
   - Ultra-fast, serverless NoSQL database storing all active and resolved findings.
   - Uses Customer-Managed KMS encryption at rest and Point-in-Time Recovery (PITR).
   - Configured with 3 Global Secondary Indexes (GSIs) to instantly search findings 
     by Severity, Category (Cost/Security), Resource ID, and Status (Open/Resolved).

4. Amazon API Gateway (HTTP API)
   - Modern, low-latency API gateway routing requests from the frontend to the 
     backend Lambda handler (/summary, /findings, /costs/trend, /chat, /scan).
   - Includes CORS configuration and Cognito JWT authorization.

5. Amazon Cognito
   - Handles enterprise user authentication, user pools, and secure login tokens 
     for security and DevOps engineers accessing the dashboard.

6. Amazon S3 (Simple Storage Service)
   - S3 Web Hosting Bucket: Hosts the compiled React 18 / Vite single-page application.
   - S3 Snapshot Archive Bucket: Stores raw JSON snapshots of every audit run with 
     versioning and automatic transition to S3 Glacier for long-term audit compliance.

7. Amazon CloudFront
   - Global Content Delivery Network (CDN) serving the frontend dashboard worldwide 
     with SSL/TLS and sub-100ms latency.
   - Uses Origin Access Control (OAC) to ensure the private S3 bucket is only 
     accessible through CloudFront.

8. Amazon EventBridge
   - Automated cloud cron scheduler.
   - Fires hourly/daily rules to trigger collector audits and a weekly rule 
     to trigger executive email digests.

9. Amazon SNS (Simple Notification Service) / Amazon SES (Simple Email Service)
   - Delivers instant alerts for critical security exposures and sends the weekly 
     executive cost & security PDF/email digests to engineers.

10. AWS KMS (Key Management Service)
    - Manages cryptographic keys to encrypt all DynamoDB records, S3 buckets, 
      and CloudWatch logs at rest.

11. AWS IAM (Identity and Access Management)
    - Manages cross-account access via `sts:AssumeRole`.
    - Has an explicit `Deny` policy on all mutating actions (e.g. ec2:Terminate*, 
      s3:Delete*, iam:Delete*) to mathematically guarantee safety.

12. Amazon CloudWatch & AWS Budgets
    - Centralized log streaming and alarms for Lambda functions.
    - Monitors cost thresholds and alerts if AWS budget is exceeded.

B. TARGET AWS SERVICES AUDITED BY CLOUGUARD AI
--------------------------------------------------------------------------------
13. Amazon EC2: Scans for running instances with <5% CPU usage over 14 days (idle waste).
14. Amazon EBS: Finds unattached storage volumes and snapshots older than 90 days.
15. Amazon VPC / Elastic IPs: Detects allocated Elastic IPs that are not attached to servers.
16. Amazon S3: Detects public bucket access, missing public access blocks, and missing lifecycle rules.
17. AWS IAM: Detects console users without Multi-Factor Authentication (MFA) and keys older than 90 days.
18. Amazon RDS: Detects public PostgreSQL/MySQL database instances exposed to the open internet.
19. AWS Cost Explorer: Analyzes 12-month billing trends and flags month-over-month spend spikes >25%.

5. SECURITY GUARANTEE: WHY IT IS 100% SAFE (READ-ONLY)
================================================================================
CloudGuard AI is built from the ground up to never modify, terminate, or delete 
any client infrastructure:

1. Code-Level Enforcement (`ReadOnlyClientProxy`):
   Every boto3 client is wrapped in a proxy class. It only allows API calls 
   starting with `describe_*`, `get_*`, and `list_*`. Any attempt to call mutating 
   APIs (like `terminate_instances` or `delete_volume`) triggers a 
   `ReadOnlyViolationError` and immediately halts execution.

2. IAM Level Guardrails:
   The AWS IAM role assumed by CloudGuard AI includes an explicit `Deny` statement 
   on all mutating API calls (`ec2:Terminate*`, `s3:Delete*`, `iam:Delete*`, etc.).

3. Display-Only Blueprints:
   Remediation code snippets (CLI / Terraform) are rendered solely on screen for human 
   review and copy-pasting. The application has no automated write/remediate pipeline.
